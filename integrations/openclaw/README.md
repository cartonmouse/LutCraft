## 业务接口

| 接口 | 调用方 | 说明 |
| --- | --- | --- |
| `POST /api/projects/{id}/instructions` | 浏览器 | OpenClaw 模式返回 202 和轮次；同一请求 ID 不重复执行 |
| `GET /api/agent-turns/{id}` | 浏览器 | 校验浏览器归属后读取轮次，不返回远端会话键和凭据 |
| `POST /api/agent-turns/{id}/cancel` | 浏览器 | 立即撤销本轮写权限并取消本地等待；不承诺远端推理停止计费 |
| `POST /internal/openclaw/hello` | 可信版本适配器 | Bearer 桥接认证，核对专用 Agent 与已验证版本 |
| `GET /internal/openclaw/catalog` | 可信版本适配器 | 返回八个工具的参数 Schema |
| `POST /internal/openclaw/invoke` | 可信版本适配器 | 携带可信 Agent/会话上下文、工具调用 ID 及模型业务参数 |

内部接口使用专用桥接令牌，不采用用户 Cookie；拒绝带浏览器 Origin 的请求，实际请求体上限 64 KiB。业务地址只能由部署配置提供，HTTP 仅允许回环地址，远端必须 HTTPS，客户端不跟随重定向。

`hello` 只证明有持有桥接令牌的适配器报告连接，不能证明模型推理可用。健康状态分别显示配置、兼容性验证标记、曾连接的插件、Gateway 最近结果和最近模型调用结果。健康轮询不触发推理。

## 会话与执行规则

会话策略在 plan3 基础上细化为：项目保留长期业务会话记录，但 **每轮生成独立的远端会话键**。由 SQLite 中本项目近期消息、配方和明确偏好构建新轮上下文。这样旧轮回调不会因复用同一个远端会话而获得下一轮权限，清除记忆也无需依赖尚未确认的远端删除接口。

每个工具调用的 Agent 与会话身份必须来自实际 SDK 的可信上下文，不能从模型参数、提示词或 URL 查询参数提取。本目录的 `RuntimeBinding` 是本项目接口类型，不是对 OpenClaw SDK 字段名的断言。该映射无法验证时，适配器必须拒绝写操作。

一个轮次允许一个成功预览和一次成功记忆修改；重复操作返回原回执，修改过参数的第二次写入被拒绝。同一个调用 ID 的内容不可更改。参数错误可以在调用上限内纠正。预览任务与回执在同一事务中提交，进程崩溃不会留下“任务存在但去重记录缺失”的正常提交窗口。

用户改变项目状态后，旧轮次不能靠重新读取最新版本继续写入。只有本轮自身提交的业务变更会推进它持有的期望版本。取消、清空对话、修改偏好、超时和服务重启均使旧轮失效。

清空对话或修改偏好后，下一轮只使用新的上下文时间界限之后的消息和当前偏好。已有照片和配方保留。远端 OpenClaw 日志不在本轮物理删除，需待实际版本确认后补齐并说明保留策略。

## 后续接入顺序

1. 取得团队来源，记录发行版/提交/镜像摘要，核对 SDK 的工具注册、上下文、会话路由和许可配置。
2. 编写薄适配器：加载时校验版本并完成握手，注册 `buildBusinessTools` 生成的工具；每轮从可信上下文建立 `RuntimeBinding`。
3. 锁定 SDK 依赖，补充真实插件清单及打包文件；验证加载、只读工具、预览工具，并检查白名单仅包含八个业务工具。
4. 在隔离数据目录配置实际版本后设置兼容性验证标记。业务服务配置 Gateway 地址和两类服务端凭据，模型凭据只放 OpenClaw。
5. 测试真实模型能选择 LUT、修改范围、继续调整和明确保存偏好；最终由网页确认、下载成品。记录版本、模型、工具回执和结果。

`.env.example` 给出业务侧变量；默认手动模式。`OPENCLAW_COMPATIBILITY_VERIFIED` 是部署者验收后的标记，不是程序自动确认版本成功的证据。当前不应设置为 true。

运行 `.venv/bin/python scripts/check_openclaw.py` 可查看待接入条件，退出码 2 表示尚未完成接入。运行 `bash scripts/check.sh` 执行业务测试、前端构建和 TypeScript 核心测试。
