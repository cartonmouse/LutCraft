## 快速启动

在项目目录中执行：

```bash
cd /path/to/LUT-Aagent
bash scripts/setup.sh
bash scripts/start.sh
```

打开 [本机工作台](http://127.0.0.1:8765)。停止服务时在启动终端按 `Ctrl+C`。完成过 setup 且没有更新依赖/前端代码时，只需要运行 start。

setup 会创建 `.venv`、安装锁定的 Python 依赖、安装前端依赖并构建；仅在 `.env` 不存在时复制配置模板，不覆盖已有密钥。需要 Python 3.11+、兼容 Vite 的 Node 和 pnpm；本机已验证 Python 3.12.14、Node 24.19.0、pnpm 11.25.0。工具不在 PATH 时，脚本可使用当前 Codex 桌面运行时的已知安装位置。换机器需自行安装这些工具。

已验证版本包括 React 19.3.1、Vite 7.3.7、FastAPI 0.162.0、Pydantic 2.14.1、pyvips 3.2.0 / libvips 8.18.7、OpenColorIO 2.6.0、NumPy 2.5.4。精确依赖见 `backend/requirements.lock` 和 `frontend/pnpm-lock.yaml`。pyvips 的 binary 扩展随依赖安装，通常不需要单独装 Homebrew libvips。

## 使用流程

1. 新建影集，导入 JPEG/PNG；每个影集最多 10 张，每张不超过 10 MB 和 2400 万像素。
2. 勾选要修改的照片。点击缩略图只是切换查看目标，不改变勾选范围。
3. 在“调色预设”导入 sRGB 照片用 `.cube`，选择并调节强度；或选择内置预设、调整四个基础参数。点击“生成预览”。只修改 LUT 时保留各张原有基础参数。
4. 检查前后对比和目标编号，点击“确认应用”。未确认时不会覆盖已应用结果。
5. 在导出面板下载单张或本批 ZIP。ZIP 附 `manifest.json`，只包含该批成功的照片，失败原因列入清单。
6. 在项目记忆面板明确保存偏好；清空对话、清除偏好分别操作，不会删除照片与已有配方。
7. 工作区右侧可将当前查看照片的已应用效果保存为个人预设，在“调色预设”管理，并在其他影集中手动选用。未确认预览须先应用或放弃。
8. “恢复原图效果（先预览）”对选中照片生成中性配方预览，点击“确认应用”后清除基础调色和 LUT；项目记忆保留。预览优先使用正在查看且已勾选的照片，否则使用所选照片中的第一张。切换回预览样张会显示待确认效果，其余照片在确认前仍显示已应用效果。它不恢复任意历史版本，也不输出原文件的逐字节副本。

成品长边最多 2560 像素，不放大小图。PNG 保留透明通道。原图始终保留，每次从原图按完整配方重新生成。不支持 RAW/HEIC、局部编辑、去物体和换背景；内置预设不等于自动逐图适配。

对话中的任务回复随实际状态更新：生成中 → 预览已生成、尚未应用 → 用户确认后的应用结果。失败、放弃、过期及被新方案替代也会明确显示。回复展示实际 LUT 和强度，“查看处理说明”列出检索需求、检索方式、所选候选的依据、目标照片、预览样张及基础参数变化；“查看预览”返回图片区。这些内容来自服务端执行记录，不采用模型声称的完成结果。无需升级数据库，已有旧对话刷新后也会显示对应任务的真实状态；旧记录缺少调整前参数时，只展示最终配方。

## LUT 与个人预设

素材收集与采购记录见 [LUT 来源与采购清单](../lut-library/SOURCES.md)。当前本地运行目录含 326 种 CUBE、89 种 CLF 照片转换版与 291 种原生 HaldCLUT；其他素材及输入版本的状态见 [收录登记表](../lut-library/intake-catalog.json)。

支持多文件或文件夹批量导入 3D `.cube`、13/17/32/33/65 网格、0–1 输入域；每批最多 50 个、合计 100 MB，单个最大 10 MB；不支持 1D、Log/HDR/ACES 转换。文件本身不能可靠标明色彩空间；未确认时可保存为待确认资产，填写依据并确认其输入、输出适用于 sRGB 照片后才可用于调色。不同来源的创意 LUT 应先用样张预览。

### 批量导入现有 LUT 库

1. 在网页左侧打开“调色预设”，滚动到“我的 LUT”。
2. 点击“选择文件夹”，选择项目中的 `lut-library/luts`。浏览器会包含风格子目录，将 `.cube` 加入导入队列，并匹配同目录 `metadata.json` 或同名 `.json`；有文件名或 SHA-256 声明时会核对。也可以点击“选择多个文件”手动多选。
3. 检查选中数量。旧工作台上传仅支持上文列出的 CUBE 网格；CLF、HaldCLUT 及扩展网格通过当前图库或单次调色目录使用。根据提供方说明勾选适用于 sRGB 照片，然后点击“开始批量导入”。不要选择 `_sources` 原包目录，避免混入 Log 等不同输入版本。
4. 查看逐项进度和“新增 / 已存在 / 失败”统计。文件按顺序上传、解析并验证；相同文件内容在当前浏览器会话内自动去重。失败不回滚其他成功文件，点击“重试失败项”仅重试失败项；格式或大小错误需要更换文件后重新选择。
5. 在导入后的 LUT 列表点击“选择并调节”，回到照片工作区调整强度，生成预览后确认应用。LUT 导入本身不修改照片。

LUT 保存在应用数据目录的 `luts/`，独立于素材归档 `lut-library/luts/`；原始素材保留。导入库可跨当前浏览器中的影集使用。成功记录刷新后仍可使用；本次文件选择及进度明细只保留在当前页面运行期间。若导入中刷新或断网，重新选择相同文件即可继续，已入库的内容会自动跳过。浏览器若不支持文件夹选择，可使用多文件选择。

顺序为方向与 sRGB 归一化 → 缩放 → 曝光、冷暖、对比度、饱和度 → LUT → 强度混合 → 编码。LUT 使用四面体插值，在 sRGB 编码域混合。0% 仅关闭 LUT 效果，仍保留基础调整；“不使用 LUT”解除引用。选择内置预设或个人预设会替换完整配方。

照片配方使用 v2，包含 LUT ID、名称、内容摘要、强度及固定的颜色解释。只改变基础参数时保留已有 LUT；每张照片仍从原图渲染。修改控件后旧预览不可确认，必须重新生成。

个人预设保存完整配方，不自动跨影集应用。删除预设不影响已有图片和任务；LUT 文件本轮不提供物理删除入口。若文件被手动删除或修改，处理会报错，旧成品仍可下载；可关闭 LUT 或恢复原图效果继续处理。LUT 引擎不可用时基础调色仍可使用。

没有自己的 LUT 时，可运行 `.venv/bin/python scripts/make_demo_luts.py`，在 `data/test-fixtures/` 生成 `warm-srgb-33.cube` 与 `warm-srgb-65.cube`。这是本项目生成的暖色演示，不代表任何相机品牌的模拟效果。

## LUT 元信息与风格检索（第四轮）

“调色预设 → 我的 LUT”支持描述、标签、别名、已验证场景、来源、兼容性依据、启用状态及强度依据的管理。旧库首次升级按文件 SHA-256 关联本地 11 款目录资料，历史 sRGB 声明保留原来源；不会变成作者或测量认证，也不会重新渲染照片。

导入后在独立队列分析标准灰阶和色块，生成测量草稿。人工描述与新建议分别保存；重新分析或重复导入不会覆盖已接受内容。描述中不自动生成“日式”或品牌复刻承诺，75% 是无建议依据时的试用档位。来源声明与实际照片表现仍需人工核对。

输入“日式小清新，不要太黄”，检索按归属、启用状态、颜色兼容性和文件完整性筛选，再融合中文关键词、同义词和可用向量；页面展示最多三款候选及理由、冲突。“不要黑白”执行排除，“不要太黄”作为偏好惩罚。没有充分匹配、名称歧义或未经验证的肤色要求时返回无匹配或澄清。

直连 Agent 首先提出检索意图，后端检索后再规划具体候选与强度。新风格重新检索；“换第二个”使用仍有效的候选快照。“第 2 张使用暖调青橙电影风格，强度 60%”只生成第 2 张的待确认预览；“第 2 张强度改为 40%”保留其余参数。候选有一小时时效，工作区、已应用照片或元信息变化会使其失效；人工按钮确认后才应用。

### 配置独立 Embedding

配置模板默认关闭 Embedding，未配置时使用关键词与同义词检索。当前本机已配置硅基流动 `BAAI/bge-m3`（2026-10-28），真实 API 连通和独立库索引已验证。无需额外向量数据库；兼容的本地 HTTP 服务也可使用，但本项目不自动安装本地模型。

在项目 `.env` 增加以下独立设置，保留现有 `MODEL_*` 对话模型配置：

```dotenv
EMBEDDING_PROVIDER=compatible
EMBEDDING_API_URL=服务商提供的完整 embeddings 地址
EMBEDDING_MODEL=实际模型名称
EMBEDDING_API_KEY=你自己的密钥
EMBEDDING_DIMENSIONS=1024
EMBEDDING_SEND_DIMENSIONS=true
EMBEDDING_VERSION=1
EMBEDDING_TIMEOUT=10
EMBEDDING_BATCH_SIZE=10
```

维度必须与模型实际返回一致；查询/文档前缀按该模型要求设置 `EMBEDDING_QUERY_PREFIX` / `EMBEDDING_DOCUMENT_PREFIX`。地址、模型、版本、维度、维度发送选项或前缀变更会隔离旧索引。不要先猜一个相似度阈值；`EMBEDDING_MIN_SIMILARITY` 留空时，只有向量命中的候选需要人工确认。

本机硅基流动配置使用 `https://api.siliconflow.cn/v1/embeddings`、`BAAI/bge-m3`、1024 维，查询和文档前缀均为空。设置 `EMBEDDING_SEND_DIMENSIONS=false`，因为[硅基流动接口](https://docs.siliconflow.cn/docs/api/embeddings-post)仅为 Qwen3 系列支持自定义维度参数；该选项不会关闭返回向量的维度校验。[BGE-M3 模型说明](https://huggingface.co/BAAI/bge-m3)确认固定 1024 维且不需要查询指令前缀。`EMBEDDING_VERSION=1` 是本地索引版本，不是提供方的不可变模型快照。

重启服务后，在库中点击“为可用 LUT 分析效果并建立索引”。任务失败可单项重试，已导入文件与已有照片保留。向量文本包含描述、标签、别名、场景和测量摘要；不会发送照片像素或整份 CUBE 数值。密钥仅在后端使用，不发给浏览器。

真实 API 配好后，可显式执行 `.venv/bin/python scripts/evaluate_lut_search.py --live-embedding --output data/qa/plan4/search-evaluation-live.json`。该命令在临时库为 11 款建索引并测试 30 条需求，会调用配置的 Embedding 服务、可能产生费用。当前评测标注只是根据目录元信息制作的初稿，尚需人工审核及样张确认，不能将通过率当作审美质量保证。

2026-10-28 真实接入结果：当前用户库 11/11 份向量就绪，分析与索引共 3.82 秒；三次实际混合搜索约 230–256 ms。30 条初稿评测中，正例 Hit@3=100%，负例正确率=70%，严格排除违反数为 0；另三条无对应风格的需求仍返回待确认候选，拒绝无匹配的能力需要继续校准。20 条执行混合检索，其余 10 条因精确名称或不支持的编辑要求走关键词/规则路径，没有 API 故障降级。结果在 `data/qa/embedding-setup/search-evaluation-live.json`，本机索引与搜索记录在 `data/qa/embedding-setup/production-index.json`。不应将这些目录初稿指标当作人工审美验证。

本机合成规模测量：1,000 / 10,000 条记录的热查询 p95 约 96 / 987 ms；包含文件校验、SQLite、文本匹配、向量融合与快照写入，排除远程 API、规划模型与网页渲染。冷查询约 160 / 3,339 ms，峰值 RSS 约 116 / 458 MiB（含构造基准数据）。报告在 `data/qa/plan4/search-scale.json`，仅供当前机器参考。

## 接入状态与后续配置

### 当前 DeepSeek 直连配置（2026-10-28 已验证）

本机 `.env` 已填写以下非敏感配置，密钥由用户自行保存，未写入文档：

```dotenv
AGENT_RUNTIME=direct
MODEL_PROVIDER=deepseek
MODEL_API_URL=https://api.deepseek.com/chat/completions
MODEL_NAME=deepseek-flash
MODEL_TIMEOUT=30
```

DeepSeek 模式使用非思考模式、JSON 输出和最多 1536 输出 token。模型负责生成受校验的调色参数，图片继续在本机处理。接口地址及模型名依据 [DeepSeek 官方接入说明](https://api-docs.deepseek.com/)，结构化输出依据 [JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/)。

已用临时影集完成 3 次真实调用：全部照片曝光 +0.2 EV、冷暖 +0.1；仅第 3 张饱和度 -0.1；保存当前影集偏好。真实预览、确认应用、ZIP 下载及偏好重启恢复通过。三次响应分别为 1.17、1.93、0.95 秒，仅代表本次测试，不保证后续请求耗时。没有发送用户照片像素或修改已有影集。

对话保留基础参数、内置预设及项目记忆能力。第四轮新增 LUT 检索、候选选择和强度调整；个人预设管理及恢复原图效果仍通过页面使用。直连采用有界两阶段规划，并不运行 OpenClaw 工具。不能把接口已接通解释为所有计划功能均已完成。

### 后续 OpenClaw 对接

在工程目录运行 `.venv/bin/python scripts/check_openclaw.py`，可检查本机 CLI、当前业务配置及健康状态。它不会安装软件、修改配置或调用付费模型。未具备运行条件时退出码为 2，并说明缺少的条件。

模型服务未来配置在 OpenClaw 侧；业务服务只持有 Gateway 和桥接凭据，浏览器拿不到它们。`.env.example` 列出业务侧配置；当前保留 `OPENCLAW_COMPATIBILITY_VERIFIED=false`；已使用直连模式进行演示，不需要更改该标记。

目标版本核实后，适配器需完成以下工作：由可信 SDK 上下文取得 Agent 和本轮会话标识；注册八个业务工具；通过 `/internal/openclaw/hello` 校验 Agent 和版本；再进行真实模型测试。当前 HTTP 客户端按官方 OpenResponses 文档实现并完成模拟协议测试，尚未验证与团队版本兼容。

每轮使用新的远端会话键，连续调整所需的近期对话、当前配方和明确偏好由业务数据库重新组装，防止上一轮迟到回调混入下一轮。清空对话或更新偏好会切断旧上下文；远端 OpenClaw 日志尚未实现物理删除，后续根据实际版本补齐。

`MODEL_API_URL`、`MODEL_NAME`、`MODEL_API_KEY` 仅在显式 `AGENT_RUNTIME=direct` 时使用；当前用于演示和真实对话。手动模式和 OpenClaw 模式不会调用该直连适配器。

OpenClaw 相关验收使用隔离测试目录和模拟 Gateway，不能证明原生平台接入成功；DeepSeek 直连已有上述真实调用记录。模型只接收文字、照片 ID/编号、配方和项目偏好，不发送照片像素；不具备自动看图判断曝光、肤色或相机风格的能力。

```text
data/<project-id>/    原图、基础预览、缩略图和逐次处理结果
data/luts/<lut-id>/   不可变 .cube 文件
data/backups/         版本升级前的 SQLite 一致备份
data/.session-secret  自动生成的持久化会话签名密钥
sites/                已有原型相关文件，未发布
```

实际数据目录可通过 `.env` 中的 `DATA_DIR` 设置；相对路径以启动目录为基准。默认启动脚本会切换到工程根目录。真实 `.env`、图片、数据库及会话密钥都在 Git 忽略范围内。

同一浏览器通过持久化 Cookie 找回项目。清除浏览器 Cookie 后无法通过原会话访问旧项目；首版没有账户恢复、跨设备同步或项目删除界面。服务只监听 `127.0.0.1`，不是公网部署方案。

使用单个后端 worker。重启后未完成任务标为中断，已成功照片保留；“重试”会只为仍有效的失败/中断项生成新预览，需要再次确认。图像任务不承诺后台自动续跑。LUT 分析/索引使用独立单线程持久队列，启动时将中断的运行项重新排队；旧元信息版本或旧模型配置的结果不会覆盖新版本。

升级至第二轮时，先停止旧服务，再运行 setup/start。首次启动会通过 SQLite backup 接口保存升级前备份，事务创建新表并设置数据库版本；旧照片、结果、对话和偏好保留。旧 v1 配方按原参数读取为 v2，无 LUT，不自动重新渲染；旧待确认预览过期，需要重做。升级后已有新写入时，不要直接用旧备份覆盖当前数据。

## 开发与检查

```bash
bash scripts/check.sh
.venv/bin/python scripts/benchmark.py
.venv/bin/python scripts/benchmark_luts.py
.venv/bin/python scripts/evaluate_lut_search.py
.venv/bin/python scripts/benchmark_lut_search.py
```

check 执行后端测试、前端批量导入队列测试、TypeScript 检查/生产构建与 OpenClaw 工具核心测试。benchmark 使用临时数据目录和 10 张合成图片，结果写入 `data/benchmark.json`；不发起模型请求，也不改用户影集。

benchmark_luts 使用相同的 10 张 2400×1600 合成 JPEG，在独立进程对比无 LUT、33 和 65 网格的冷/热预览、整批和内存，写入 `data/benchmark-luts.json`。当前本机测得 LUT 整批约 3.9–4.0 秒；包含测试客户端的峰值 RSS 约 367–412 MiB，不能作为其他机器、真实照片或模型调用的耗时承诺。混合运算按 128 行分块，保持一个图像工作线程。

开发前端时，在 `frontend/` 执行 `pnpm dev`，API 默认代理到 8765 端口的后端。设置自定义端口需同步修改 Vite 代理。生产构建文件由 FastAPI 在根路径提供。
